# Albums — план: голосовые к кадрам, сборная история, блочный редактор «Истории»

Дата: 2026-07-27 (обновлён: + статистика прослушиваний, + полный разбор безопасности).

Задача:

1. **Сохранить** существующую озвучку (вариант 1): один рассказ на альбом + метки
   «на секунде N показать этот кадр», расставляемые тапами при прослушивании
   (`js/narration.js`, миграция 012). Не трогаем.
2. **Добавить** вариант 2: голосовое описание к отдельному кадру — зажал кнопку у
   фото/видео, записал, отпустил. Сервис собирает из дорожек полноценную
   аудио-историю и играет слайд-шоу с единым таймлайном.
3. **Блочный редактор** части «История»: перестановка блоков фото/видео/текст,
   объединение фото в галереи, прикрепление голосовых к кадрам и галереям.
4. **Статистика прослушиваний** истории: пока только количество; засчитывается
   любое прослушивание длиннее 5 секунд; считается общая дорожка истории.

---

## 0. Утверждённые решения (ответы владельца, 2026-07-27)

1. **Сборка аудио — виртуальная.** Плеер играет дорожки подряд, единый таймлайн
   рисуется поверх (кумулятивные смещения). Ничего не перекодируется, перезапись
   голоса к одному кадру ничего не пересобирает. Экспорт одним файлом — позже,
   модель это позволяет.
2. **Голосовая прикрепляется и к кадру, и к галерее.** Пока звучит голосовая
   галереи, её кадры сменяются равномерно: длительность дорожки / число кадров.
3. **Один активный режим истории на альбом.** Автор в редакторе выбирает источник:
   единый рассказ (вариант 1) ИЛИ сборка из голосовых (вариант 2). Обе
   конфигурации хранятся, переключение без потери. Зритель видит одну кнопку.
4. **Главы остаются разделами** (label / заголовок / текст — как сейчас). Блоки
   переставляются внутри глав. Старые альбомы выглядят без изменений; авто-главы
   и календарь не трогаем.
5. **Прослушивания истории считаем** (2026-07-27): только количество; порог —
   5 секунд; считается общая дорожка истории (не отдельные плашки у кадров).

## 1. Решения по умолчанию — поправь, если что-то не так

1. Одиночный кадр **без** голосовой показывается в истории ~2.5 с в тишине —
   из рассказа ничего не выпадает. (Вариант «пропускать» — одна константа.)
2. Видео без голосовой играет в истории **со своим звуком** целиком; видео с
   голосовой — беззвучно, на длительность голосовой (как в варианте 1).
3. Голосовые слышны и без слайд-шоу: в story-виде у озвученного кадра/галереи —
   плашка ▶ с волнограммой (как у войс-заметок). Эти прослушивания в статистику
   **не** входят (считаем только общую дорожку, решение §0.5).
4. Голосовые **не входят** в `audio_count` и бейдж «N photos · M videos» —
   как и дорожка рассказа.
5. Текстовые блоки в слайд-шоу не показываются, только в чтении (титульные
   карточки — возможная полировка позже).
6. Гости событийного альбома голосовые пока **не** записывают: модель данных
   готова, UI — отдельной задачей.
7. Перетаскивание: drag&drop на десктопе, ↑/↓ и «в главу…» на телефоне
   (long-press-drag конфликтует со скроллом).
8. Лимит голосовой — 5 минут (проверка на клиенте); лимиты аудио-файла прежние
   (20 МБ free / 50 МБ Pro, сервер r2-sign проверяет по тарифу).
9. Grid-режим галереи не группирует — там и так все кадры подряд.
10. Голосовая галереи видна тому, кому виден альбом **и** хотя бы один кадр
    галереи (голос к полностью скрытой галерее не подписывается).
11. Перезапись/открепление голосовой **удаляет старую строку media** (если она
    больше нигде не используется) — голосовые не копятся в библиотеке и квоте.
12. «Прослушивание» = 5 секунд реальной работы таймлайна истории (паузы не
    считаются). Повторный запуск слайд-шоу — новое прослушивание; для
    залогиненных сервер дополнительно склеивает повторы в течение 60 секунд.
13. Счётчик прослушиваний видит только автор (страница статистики). Публично
    не показывается.

## 2. Модель данных — миграция 034

Только новые объекты + переписывание ядра (см. §3). Данные существующих альбомов
не мигрируются: все новые колонки nullable, старое поведение — значения по
умолчанию.

```sql
-- источник истории: null = авто (голосовые, если есть; иначе рассказ)
alter table albums add column if not exists story_mode text
  check (story_mode in ('narration','voices'));

-- галерея: группа кадров, у группы может быть общая голосовая
create table if not exists album_galleries (
  id             uuid primary key default gen_random_uuid(),
  album_id       uuid not null references albums(id) on delete cascade,
  voice_media_id uuid references media(id) on delete set null,
  created_at     timestamptz not null default now()
);

alter table album_media add column if not exists voice_media_id uuid
  references media(id) on delete set null;
alter table album_media add column if not exists gallery_id uuid
  references album_galleries(id) on delete set null;

-- текстовый блок в общей последовательности позиций с album_media
create table if not exists album_texts (
  id         uuid primary key default gen_random_uuid(),
  album_id   uuid not null references albums(id) on delete cascade,
  chapter_id uuid references album_chapters(id) on delete set null,
  position   int not null default 0 check (position >= 0),
  body       text not null check (length(body) <= 4000),
  created_at timestamptz not null default now()
);

-- прослушивания истории — новый вид события в существующем логе
alter table stat_events drop constraint stat_events_kind_check;
alter table stat_events add constraint stat_events_kind_check
  check (kind in ('impression','view','button','listen'));
```

Индексы: `album_media(voice_media_id)`, `album_media(gallery_id)`,
`album_galleries(voice_media_id)`, `album_texts(album_id, position)`.

RLS: `album_texts`, `album_galleries` — SELECT по `can_view_album`; запись —
только через RPC (политик записи нет). `stat_events` — как было: политик нет
вообще, чтение и запись только через DEFINER-функции.

Решения модели:
- **Длительность голосовой не дублируем** — берётся из `media.duration_seconds`
  (клиент заполняет при загрузке, как сейчас).
- Порядок истории — **одна числовая последовательность** `position` на альбом,
  общая для `album_media` и `album_texts`; позиция галереи = позиция её первого
  кадра, кадры галереи идут подряд. Перенумерацию делает RPC атомарно.
- Голосовые — обычные строки `media` (kind=audio) в приватном хранилище, тем же
  путём загрузки (`uploadMedia` → r2-sign). Квота учитывается автоматически
  (`r2_reservations`).
- **Отдельного счётчика в albums нет**: прослушивания читаются агрегатом из
  `stat_events` (как показы/посещения) — меньше триггеров, меньше поверхность.

## 4. Новые RPC (SECURITY DEFINER, `auth.uid()` обязателен, `set search_path = public`)

| RPC | Что делает | Валидация |
|---|---|---|
| `album_voice_set(p_am, p_media)` | прикрепить голосовую к кадру | `can_edit_album`; **media.kind='audio' и owner_id = auth.uid()**; кадр принадлежит альбому и не audio; старая голосовая удаляется из media, если больше нигде не используется |
| `album_voice_clear(p_am)` | открепить (+ удалить неиспользуемую строку media) | `can_edit_album` |
| `album_gallery_group(p_album, p_am_ids uuid[])` → id | собрать галерею | `can_edit_album`; 2–30 кадров; **каждый id принадлежит p_album**; одна глава; kind≠audio; кадрам — последовательные позиции |
| `album_gallery_ungroup(p_gallery)` | разобрать (голос галереи открепляется и чистится) | `can_edit_album` |
| `album_gallery_voice_set / _clear` | голосовая галереи | как у voice_set |
| `album_text_upsert(p_id?, p_album, p_chapter?, p_body)` | текстовый блок | `can_edit_album`; длина ≤4000; ≤200 блоков на альбом; p_chapter принадлежит p_album |
| `album_text_delete(p_id)` | удалить блок | `can_edit_album` |
| `album_story_reorder(p_album, p_items jsonb)` | порядок истории: `[{t:'m'\|'x', id}]` → единая перенумерация позиций media+texts; кадры галереи подряд | `can_edit_album`; массив ≤1000; **каждый id принадлежит p_album** (чужие молча пропускаются, как в narration_cues_set) |
| `album_story_mode_set(p_album, p_mode)` | 'auto' (null) / 'narration' / 'voices' | `can_edit_album` |
| `stat_listen(p_album, p_country?, p_lang?)` | прослушивание истории (§8) | `can_view_album`; автор не считается; authed — не чаще 1 раза в 60 с по (альбом, слушатель) |

Гранты: все пишущие — **только authenticated**; `stat_listen` — anon +
authenticated (как `stat_track`). Перед каждым grant — явный
`revoke from public, anon, authenticated` (гоча 020: Supabase раздаёт execute
новым функциям сам). `narration_set/clear/cues_set/get` — без изменений.

## 5. Общий плеер истории — `js/storyplayer.js` (новый)

Один фуллскрин-оверлей на оба режима (сейчас он живёт внутри narration.js):
полоса с метками, пауза, seek, Esc/пробел, подписи кадров.

- Вход — список сегментов: `{frames:[{am_id,…}], dur, track:url|null, videoOwnSound?}`
  и суммарная длительность. Сегменты строятся клиентом из `get_album`:
  - кадр с голосовой → сегмент на длительность дорожки;
  - галерея с голосовой → один сегмент, кадры сменяются каждые `dur/n`;
  - одиночный кадр без голоса → 2.5 с тишины (§1.1);
  - видео без голоса → сегмент на длительность видео, звук самого видео.
- **Вариант 1 (рассказ)**: один трек, сегменты из `narration_cues`.
  `mountNarrationPlayer` становится тонкой обёрткой над общим плеером — API и
  редактор меток в narration.js не меняются.
- **Вариант 2 (голосовые)**: очередь дорожек. **Один `<audio>` на весь показ**,
  переключаем `src` по очереди — iOS разрешает программный `play()` только на
  элементе, уже активированном жестом пользователя. Тишина — таймер. Следующая
  дорожка предзагружается.
- Seek по единому таймлайну: кумулятивные смещения → сегмент + позиция в дорожке.
- Переподпись протухших R2-ссылок — существующий `attachMediaRefresh`.
- **Счётчик прослушиваний**: плеер копит время реальной работы таймлайна (паузы
  не считаются) и на отметке 5 с один раз вызывает `stat_listen` через `fire()`
  из stats.js (ошибки глушатся — статистика не ломает плеер).

Риск: рефакторинг задевает вариант 1 → обязательный регресс-прогон на
существующем альбоме с озвучкой (§11).

## 6. Редактор «Истории» — `js/storyeditor.js` (новый), подключается из editor.js

Секция «Медиа» редактора превращается в блочный список истории (текущая
функциональность карточки сохраняется полностью: подпись, глава, приватность,
обложка, удалить):

- **Блоки**: медиа-кадр / галерея (стопка превью) / текст. Порядок = позиция;
  сгруппированы по главам. Перестановка: drag&drop (desktop) + ↑/↓ (везде);
  каждое перемещение — один вызов `album_story_reorder` (оптимистично, как
  текущий `move()`).
- **Галереи**: чекбоксы выбора кадров → кнопка «Объединить в галерею»; на
  галерее — «Разобрать». Подсказка: галерея живёт внутри одной главы.
- **Тексты**: «+ Текст» → textarea (≤4000), сохранение по change, как главы.
- **Голосовые**: кнопка 🎙 на кадре и галерее. Зажать — запись (MediaRecorder,
  pointer events: pointerdown/pointerup/pointercancel, `touch-action:none`,
  отмена уводом пальца; < 0.7 с — подсказка «зажмите и говорите»). Отпустил →
  предпрослушка → сохранить / перезаписать / удалить. На десктопе рядом
  «загрузить файл» (audio/*). Загрузка — существующий `uploadMedia` (стадии,
  busy-счётчик блокирует публикацию), затем `album_voice_set`.
  Микрофонный stream останавливается сразу по окончании записи; запись рвётся
  при закрытии модалки/сворачивании страницы.
- **Блок «История»** (вместо нынешней секции «Озвучка»): переключатель источника
  (авто / единый рассказ / голосовые), кнопка старого редактора меток
  (`openNarrationEditor` без изменений), суммарная длительность сборки и счётчик
  озвученных кадров.

## 7. Показ

- `albumview.js` — **общий с панелью модерации**, правится один раз:
  тексты в своих позициях; галерея — карусель (стрелки/свайп, паттерн карусели
  постов); у озвученного кадра/галереи — плашка ▶ с длительностью. Grid-режим
  не меняется.
- `album.js`: кнопка «История» — по `story_mode`/наличию
  (`has_narration || has_voices`), в подписи — суммарная длительность; вызов
  общего плеера в нужном режиме.
- `moderation.js`: новые ключи приходят из переписанного `mod_open_album`;
  рендер общий, но панель проверяется руками отдельно (§11).
- `statspage.js`: плитка «Прослушивания истории» в сводке + колонка в таблице
  альбомов (данные из обновлённого `stats_summary`).

## 8. Статистика прослушиваний

Ложится в существующий слой `stat_events` (021) — новых таблиц нет.

- **Событие**: `kind='listen'`, `album_id`, `owner_id` (автор), `actor_id`
  (слушатель, null у гостя), страна/язык как у `stat_track` (из часового пояса
  и настроек браузера; **IP не собираем** — правило слоя статистики).
- **Порог**: клиент шлёт событие один раз за показ слайд-шоу, когда таймлайн
  истории проработал 5 секунд суммарно (паузы не считаются). Работает одинаково
  для обоих режимов — хук в одном месте, в общем плеере (§5).
- **RPC `stat_listen`** (по образцу `stat_track`): `can_view_album` (приватный
  альбом постороннему возвращает null — существование не светится), автор сам
  себе прослушивания не наматывает, залогиненный — не чаще одного события в
  60 секунд по паре (альбом, слушатель), гость — простая вставка (тот же
  принятый компромисс, что у просмотров).
- **Показ**: только автору — `stats_summary` получает `totals.listens` и
  `albums[].listens`; на странице статистики — плитка и колонка. Публичных
  счётчиков прослушиваний нет.
- Не считаются: плашки ▶ у отдельных кадров (§1.3), прослушивания автором.
- Легко добавить позже (не сейчас): график по дням, дослушиваемость
  (dwell-паттерн, как удержание страницы), прослушивания в `admin_stats`.

## 9. Безопасность: БД / пользователи / сервер

Новая поверхность: 6 переписанных функций ядра, ~10 новых RPC, 2 новые таблицы,
3 колонки, один анонимный endpoint статистики, запись с микрофона. По угрозам:

### 9.1 База данных

1. **Кража чужого файла через «голосовую»** — главная новая атака: без проверки
   владения `album_voice_set(p_am, ЧУЖОЙ_media_id)` сделал бы чужой приватный
   файл видимым через новую ветку `can_view_media` (и подписываемым в r2-sign).
   Ответ: `media.owner_id = auth.uid()` и `kind='audio'` в обоих voice-RPC —
   та же проверка, что в `narration_set` («можно использовать только свою
   запись»). Негативный тест обязателен (§11).
2. **Порча чужих альбомов через DEFINER** (RPC обходит RLS): каждый id из
   аргументов проверяется на принадлежность `p_album` (reorder, галереи,
   тексты, p_chapter) — паттерн `narration_cues_set` / `album_media_reorder`;
   сам `p_album` — через `can_edit_album`.
3. **Гоча «admin=authenticated»**: каждый новый RPC начинается с проверки
   `auth.uid() is not null`; гранты точечные: пишущие — только authenticated,
   `stat_listen` — anon+authenticated; перед grant — явный revoke (гоча 020).
4. **Переписывание ядра**: источник тела один (§3), снимок `pg_proc` до и после,
   diff «старое тело + только новые ветки»; `create or replace` сохраняет ACL,
   но revoke на `mod_open_album` re-assert'ится явно (паттерн 021/023).
5. **search_path hijack**: `set search_path = public` на каждой новой функции
   (правило всего проекта).
6. **Границы входов** (DoS через раздутые аргументы): reorder ≤1000 элементов,
   текст ≤4000 символов и ≤200 блоков на альбом, галерея 2–30 кадров, голосовая
   ≤5 мин (клиент) и ≤20/50 МБ по тарифу (сервер r2-sign), jsonb проверяется на
   тип массива (как `narration_cues_set`).
7. **RLS новых таблиц**: enable сразу после create, политик записи нет (только
   RPC), SELECT — `can_view_album`, `grant select` точечно. `stat_events` — как
   был: политик нет, доступ только через DEFINER.
8. **Каскады**: кадр удалён → `voice_media_id` set null; галерея удалена → у
   кадров set null; альбом удалён → cascade; глава удалена → тексты в «прочее»
   (set null, как медиа). Осиротевших ссылок не остаётся.

### 9.2 Пользователи (приватность)

1. **Голос — чувствительные данные** (фактически биометрия). Видимость голосовой
   = видимость её **кадра**, не альбома: скрытый кадр → голосовую не подпишут
   никому, кроме владельца файла и редакторов; friends-only кадр → только
   друзьям автора; голосовая галереи — только при хотя бы одном видимом кадре.
   Полная матрица — в §11.
2. **Хранение** — тот же приватный R2: только подписанные URL с TTL, стабильных
   публичных ссылок нет; ключ объекта строит сервер (r2-sign), клиентские пути
   не принимаются.
3. **Микрофон**: запись только пока кнопка зажата; `stream.getTracks().stop()`
   сразу по окончании (как в narration.js); pointercancel / закрытие модалки /
   сворачивание страницы обрывают запись — индикатор микрофона не «зависает»,
   фоновой записи нет. Несохранённая запись никуда не уходит.
4. **Статистика прослушиваний**: только числа. IP не собирается (весь слой
   статистики живёт без IP — правило 021), список «кто слушал» не существует
   ни в одном интерфейсе, автор видит агрегаты. Свои прослушивания не считаются.
5. **Право на удаление**: перезапись/открепление голосовой удаляет строку
   `media`; квота освобождается (ленивая чистка `r2_reservations` по отсутствию
   строки, окно 2 ч — проверено по 019). R2-объект остаётся сиротой до общей
   уборки — существующее поведение всего медиа-слоя, в квоте не участвует;
   уборка сирот — отдельная задача (§12).
6. **Модерация и жалобы**: `mod_open_album` отдаёт голосовые, тексты и галереи —
   модератор слушает ровно то, что уедет на сайт; жалоба на альбом покрывает
   его голосовые. Голосовые гостей событий отложены, но «придержать гостевое»
   уже распространяется на модель.
7. **XSS**: тексты блоков, подписи, всё пользовательское — только `textContent`
   (правило ARCHITECTURE §8.4); в плеере и карусели тоже.

### 9.3 Сервер / инфраструктура

1. **Новых edge-функций и секретов нет.** r2-sign не меняется: голосовые идут
   через его rate-limit (`r2_rate`) и квоту (`r2_reserve_upload` под
   advisory-lock) — накрутить хранилище или обойти тариф нельзя.
2. **`stat_listen` — единственный новый анонимный вход**: одна вставка под
   `can_view_album`; дедуп 60 с для залогиненных; анонимная накрутка возможна
   в той же мере, что у просмотров (принятый риск MVP: цифра видна только
   автору, в ранжирование не входит). Rate-limit триггером — фаза 3
   (ARCHITECTURE §8.9), таблица под это уже готова.
3. **Нагрузка**: `get_album` потяжелел на подзапросы по новым индексам
   (`voice_media_id`, `gallery_id`, `album_texts(album_id,position)`);
   `can_view_media` +2 exists по индексам — профиль батч-подписи прежний;
   `stat_events` спроектирован под поток (индексы по day), listens его не
   меняют. Прослушивания не трогают горячие ленты.
4. **CSP всех страниц не меняется**: запись и воспроизведение — нативные API,
   новых хостов нет, wasm не нужен.
5. **Откат**: 034 обратно-совместима (nullable-колонки, только новые ключи в
   выдачах, сигнатуры не меняются) — откат = вернуть фронт прежним коммитом,
   базу не трогать. Отката миграции не требуется.
6. **Деплой БД** — как всегда через Management API (`tools/sql.ps1`), токен вне
   репозитория; в миграции нет секретов.
